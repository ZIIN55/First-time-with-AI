**1. 📝 บทคัดย่อ (Abstract)**
โครงงานวิศวกรรมฉบับนี้มีวัตถุประสงค์เพื่อพัฒนาและประเมินประสิทธิภาพของระบบปัญญาประดิษฐ์ (AI) สำหรับการจำแนกท่าทางของมือมนุษย์ 3 รูปแบบหลัก ได้แก่ **"ค้อน" (Rock)**, **"กรรไกร" (Scissors)** และ **"กระดาษ" (Paper)** โดยอาศัยการประยุกต์ใช้เทคนิคการเรียนรู้ถ่ายโอน (Transfer Learning) บนสถาปัตยกรรมโครงข่ายประสาทเทียมเชิงลึกผ่านเครื่องมือ Google Teachable Machine ระบบถูกออกแบบมาให้สามารถประมวลผลภาพนิ่งและภาพเคลื่อนไหวจากเว็บแคมได้แบบเรียลไทม์ (Real-time Processing) จากการทดลองในระยะแรกพบปัญหาข้อจำกัดทางเทคนิค กล่าวคือ เกิดภาวะการคาดเดาสุ่มผิดพลาด (False Positives) ในสภาวะที่ไม่มีวัตถุหรือไม่มีมือปรากฏอยู่ในเฟรมภาพ ทีมงานจึงได้ทำการแก้ปัญหาเชิงสถาปัตยกรรมด้วยการเพิ่ม **"Background Class"** เข้าไปในชุดข้อมูลการฝึกสอน ผลการทดลองเชิงประจักษ์หลังการปรับปรุงชี้ให้เห็นว่า โมเดลมีความแม่นยำสูงกว่า 95% มีความเสถียร ทนทานต่อสภาวะแสงที่เปลี่ยนแปลง และสามารถตัดเข้าสู่สถานะพื้นหลังได้อย่างแม่นยำไร้รอยต่อ

**2. 🎯 ที่มาและความสำคัญของปัญหา (Introduction & Motivation)**
การปฏิสัมพันธ์ระหว่างมนุษย์และคอมพิวเตอร์ (Human-Computer Interaction: HCI) ในยุคดิจิทัลปัจจุบัน ได้ก้าวข้ามผ่านขีดจำกัดของการใช้อุปกรณ์กายภาพแบบดั้งเดิม เช่น คีย์บอร์ดและเมาส์ ไปสู่การใช้เทคโนโลยีการมองเห็นของคอมพิวเตอร์ (Computer Vision) และการจดจำท่าทาง (Gesture Recognition) โครงงานนี้จึงได้เลือกหยิบยกเกมพื้นฐานอย่าง **"เป่ายิ้งฉุบ"** มาพัฒนาเป็นกรณีศึกษาเชิงวิศวกรรมภายใต้รายวิชา DSEEE เนื่องจากเป็นโจทย์ที่มีความท้าทายในการจำแนกความแตกต่างของรูปร่างโครงสร้างมือที่มีความใกล้เคียงกันในเวลาอันรวดเร็ว ความสำเร็จของโครงงานนี้ไม่เพียงแต่ตอบสนองความเข้าใจในเชิงทฤษฎีด้านปัญญาประดิษฐ์ แต่ยังเป็นรากฐานสำคัญต่อยอดไปสู่ระบบอัตโนมัติอัจฉริยะ (Smart Automation) และเทคโนโลยีความจริงเสริม (AR/VR) ในอนาคต

**3. 🎯 วัตถุประสงค์ของโครงงาน (Research Objectives)**
* 3.1 เพื่อศึกษาและทำความเข้าใจกระบวนการสร้าง การปรับแต่งพารามิเตอร์ และการฝึกสอนโมเดลปัญญาประดิษฐ์ประเภท Image Classification ภายใต้บริบทของวิชา DSEEE
* 3.2 เพื่อพัฒนาโมเดลจำแนกท่าทางมือ 3 รูปแบบหลัก (Rock, Paper, Scissors) ให้มีอัตราความแม่นยำ (Accuracy) สูงกว่า 95%
* 3.3 เพื่อวิเคราะห์ปัญหาข้อจำกัดทางเทคนิค เช่น การเกิดภาวะ False Positives ในสภาวะที่ไม่มีวัตถุ และนำเสนอแนวทางแก้ไขด้วยการเพิ่มคลาสควบคุมพิเศษ (Background Class)
* 3.4 เพื่อบูรณาการองค์ความรู้ทางด้านวิศวกรรมดิจิทัล สู่การพัฒนาซอฟต์แวร์ต้นแบบที่สามารถใช้งานได้จริงในสภาพแวดล้อมจริง

**4. 📚 ทฤษฎีและสถาปัตยกรรมเทคโนโลยีที่เกี่ยวข้อง (Theoretical Framework)**
* **Computer Vision:** สาขาหลักของปัญญาประดิษฐ์ที่มุ่งเน้นการให้ระบบคอมพิวเตอร์สามารถประมวลผล วิเคราะห์ และทำความเข้าใจข้อมูลภาพดิจิทัลในรูปแบบเดียวกับ (หรือเหนือกว่า) มนุษย์
* **Convolutional Neural Network (CNN) & MobileNet:** โครงข่ายประสาทเทียมเชิงลึกที่ถูกออกแบบมาเป็นพิเศษสำหรับการประมวลผลภาพ โดยสถาปัตยกรรม MobileNet เน้นความกะทัดรัด น้ำหนักเบา เหมาะสำหรับการประมวลผลแบบเรียลไทม์บนอุปกรณ์ที่มีทรัพยากรจำกัด
* **Transfer Learning:** เทคนิคการนำโมเดลพื้นฐานที่ได้รับการฝึกฝนล่วงหน้า (Pre-trained Model) มาปรับจูน (Fine-tuning) ด้วยชุดข้อมูลเฉพาะของเรา ทำให้ใช้เวลาและทรัพยากรในการคำนวณน้อยลงแต่ได้ประสิทธิภาพสูง
* **Real-time Latency Optimization:** การควบคุมเวลาหน่วงในการประมวลผลภาพต่อเฟรมให้อยู่ในระดับต่ำกว่า 100 มิลลิวินาที เพื่อให้การตอบสนองมีความลื่นไหล

**5. ⚙️ ระเบียบวิธีวิจัยและขั้นตอนการดำเนินงาน (Research Methodology)**
การดำเนินงานโครงงานนี้ยึดหลักวงจรการพัฒนาทางวิศวกรรมระบบ (Engineering Design Cycle) ซึ่งแบ่งออกเป็น 5 เฟสอย่างเป็นระบบ ดังนี้:
1. **Phase 1: System Requirements & Architecture Design** – ออกแบบแผนผังการทำงาน (Flowchart) และกำหนดขอบเขตระบบ
2. **Phase 2: Dataset Curation & Acquisition** – ดำเนินการเก็บรวบรวมภาพถ่ายท่าทางภายใต้เงื่อนไขความหลากหลาย
3. **Phase 3: Model Training & Hyperparameter Tuning** – ตั้งค่าตัวแปรการเรียนรู้และกระบวนการฝึกสอนโมเดล
4. **Phase 4: Iterative Debugging & Optimization** – ตรวจสอบข้อผิดพลาดระหว่างการทดสอบและแก้ไขด้วยคลาสพิเศษ
5. **Phase 5: Final Evaluation & Deployment** – ประเมินประสิทธิภาพขั้นสุดท้ายและเผยแพร่ระบบผ่านเว็บแอปพลิเคชัน

**6. 🛠️ การออกแบบระบบ การเก็บข้อมูล และการฝึกสอนโมเดล (System Design & Implementation)**

**6.1 กระบวนการเก็บรวบรวมชุดข้อมูล (Dataset Acquisition Strategy)**
เพื่อป้องกันปัญหาการเรียนรู้เกินพอดี (Overfitting) ทีมงานได้ให้ความสำคัญกับการสร้างความหลากหลาย (Diversity) ของชุดข้อมูลภาพ:
* **โครงสร้างคลาส:** กำหนดให้มีคลาสหลักทั้งสิ้น 4 คลาส ได้แก่ Rock, Paper, Scissors และ Background
* **ขนาดตัวอย่างข้อมูล:** จัดเก็บภาพถ่ายรวมทั้งสิ้นกว่า 3,360 ภาพ (เฉลี่ย 840 ภาพต่อคลาส)
* **การควบคุมตัวแปรแวดล้อม (Environmental Control):**
  * 📐 **มุมมองเชิงมิติ (Angles):** บันทึกภาพในมุมมองตรง มุมเฉียงซ้าย และมุมเฉียงขวา เพื่อจำลองท่าทางของมนุษย์ที่อาจไม่สมบูรณ์
  * 📏 **ระยะห่างจากกล้อง (Distance):** ควบคุมระยะตั้งแต่ใกล้กล้องไปจนถึงระยะห่างมาตรฐานประมาณ 1 เมตร
  * 💡 **สภาวะแสงสว่าง (Lighting Conditions):** ทดสอบและเก็บข้อมูลภายใต้แสงหลอดฟลูออเรสเซนต์ในห้องเรียน และแสงธรรมชาติจากริมหน้าต่าง

**6.2 การตั้งค่าพารามิเตอร์และการฝึกสอน (Hyperparameter Tuning)**
* **Epochs:** กำหนดจำนวนรอบการเรียนรู้ไว้ที่ **100 Epochs** เพื่อให้โมเดลมีเวลาเพียงพอในการสกัดฟีเจอร์ (Feature Extraction) ของมือโดยไม่ทำให้เกิด Overfitting
* **Learning Rate & Batch Size:** ใช้ค่ามาตรฐานที่ได้รับการปรับจูนให้เหมาะสมกับสถาปัตยกรรม MobileNet ภายใน Google Teachable Machine
* **Convergence Verification:** ติดตามพฤติกรรมการลู่เข้าของระบบผ่านกราฟแสดงค่า Loss ที่ลดลงต่ำกว่า 0.1 และค่า Accuracy ที่ทะยานขึ้นเหนือ 95%

**7. 🔍 การวิเคราะห์ข้อผิดพลาดและการปรับปรุงระบบ (Error Analysis & Optimization)**

**7.1 ปัญหาการคาดเดาสุ่มในสภาวะว่าง (False Positives in Empty Frames)**
* **ปัญหาที่พบ:** ในระหว่างการทดสอบขั้นต้น ทีมงานพบว่าเมื่อผู้ทดลองนำมือออกจากเฟรมภาพ (เหลือเพียงฉากหลังหรือโต๊ะเรียน) โมเดลกลับแสดงพฤติกรรมการทำนายผิดพลาด โดยคาดเดาสุ่มว่าเป็นคลาส Rock หรือ Paper ด้วยค่าความมั่นใจ (Confidence Score) ที่สูงเกินจริง
* **สาเหตุเชิงวิศวกรรม:** เนื่องจากโมเดลถูกฝึกสอนด้วยภาพที่มีแต่มือ ทำให้มันขาดข้อมูลอ้างอิงของสภาวะ "ความว่างเปล่า" เมื่อเจอพื้นหลังโล่งๆ โมเดลจึงพยายามจัดหมวดหมู่ให้เข้ากับคลาสที่มีอยู่เดิม

**7.2 แนวทางแก้ไขด้วย Background Class Implementation**
* **การดำเนินการ:** ทีมงานได้เพิ่มคลาสที่ 4 เรียกว่า **"Background Class"** โดยการบันทึกภาพเฟรมพื้นที่ว่างเปล่า (ผนังห้อง, โต๊ะเรียน, บรรยากาศรอบข้าง) ในมุมมองและสภาพแสงเดียวกันจำนวนประมาณ 800 ภาพ
* **ผลลัพธ์เชิงสถาปัตยกรรม:** การเพิ่ม Background Class เปรียบเสมือนการสร้างขอบเขตการตัดสินใจ (Decision Boundary) ที่ชัดเจน ทำให้ AI สามารถแยกแยะระหว่าง "การแสดงท่าทาง" กับ "การไม่มีวัตถุ" ได้อย่างสมบูรณ์แบบ

**8. 📊 ผลการทดลองและการอภิปรายผลเชิงประจักษ์ (Results & Discussion)**

> 🔬 **สรุปผลการประเมินประสิทธิภาพของระบบหลังการปรับปรุง:**
> * **การตอบสนองต่อท่าทาง (Gesture Response):** เมื่อผู้ใช้งานแสดงท่าทาง Rock, Paper หรือ Scissors หน้าจอแสดงผลจะอัปเดตแถบ Confidence Score พุ่งสูงแตะระดับ **99% - 100%** ทันทีอย่างเสถียร
> * **การจัดการสถานะว่างเปล่า (Background Transition):** เมื่อนำมือออกจากเฟรมกล้อง ระบบสามารถตัดเข้าสู่สถานะ Background ได้อย่างรวดเร็วและแม่นยำ ปัญหาการคาดเดาสุ่มถูกกำจัดจนหมดสิ้น
> * **ความทนทานต่อสภาพแวดล้อม (Robustness):** จากการทดสอบการเปลี่ยนแปลงท่าทางอย่างรวดเร็ว (Dynamic Gesture) ภายใต้สภาวะแสงจำกัด ระบบยังคงรักษาอัตราความถูกต้องไว้ได้อย่างยอดเยี่ยม

• การแก้ปัญหาอย่างมีระบบ: สามารถแก้ปัญหา Classification Accuracy Problems (CANTs) หรือการทายมั่วจากฉากหลัง ด้วยเทคนิคการเพิ่ม Dataset คลาส Background ซึ่งทำให้โมเดลมีความเสถียรและตัดการทำงานได้อย่างถูกต้องเมื่อไม่มี Input  
• ประสิทธิภาพระดับสูง: AI ตอบสนองได้แบบ Real-time มีค่า Confidence สูงถึง 100% และพร้อมให้นำไปใช้งานหรือศึกษาต่อผ่าน GitHub
